# 작업 방식 (WORKFLOW-REVISION-001)

- **페르소나 1차 초안 = Claude Code 책임**. 챗AI 는 canon 본체 .md 접근 불가하므로 1차 초안 작성 X. Claude Code 가 `persona.md` + `manifest.yaml` + `<analyst_id>-canon-extracts.md` 3종을 한 세트로 산출.
- **챗AI = 검증·정제 책임**. 회장이 위 3종을 chat AI project 에 업로드 → 챗AI 가 7종 체크리스트로 검증.
  - 체크리스트: (1) 8섹션 양식 완비 (2) 명제 ID 체계 정합 (3) 풀이 한 줄 정의 (4) Cross-Agent Boundaries 충돌 X (5) Anti-patterns 강조도 최소 5건 (6) wealth_strategist ground truth 와 portable 일관 (7) 자료 0 시드 솔직성
  - 보고는 변경 권고 bullet 3~7건만. **결단 의제 던지지 X.**
- **8 섹션 / Anti-patterns / 명제 ID 체계 — 양식 유지**. Claude Code 가 `wealth_strategist` ground truth 양식 그대로 미러. 챗AI 가 체크리스트 #1·#5·#2 로 확인.
- **최종본 = Claude Code 산출**. 챗AI 가 직접 페르소나 .md 코드블록 출력 X. 챗AI 산출물 = 검증 보고 + 변경 권고 + Claude Code 인수 메시지.
- **canon-extracts 동봉 의무**. Claude Code 가 페르소나 작성 시 명제 추출본 (`idea_memo/canon-extracts/<analyst_id>-canon-extracts.md`) 을 반드시 함께 생성. 챗AI 의 대리 grounding 자료.

# 근거 명제 표기법법

### 1. `cited` 코드 라인
- `cited: [<명제 ID 콤마 구분>]` 한 줄. 인용 없으면 `cited: []` + 본문에 "framework 밖" 명시
- 코드성 메타 마커. 격자 cell 안 명제 표기와 일관

### 2. 근거 명제 풀이 (bullet)
`cited` 의 각 명제 ID 마다 한 줄씩:

```
근거 명제 풀이:
- <ID> (<dept 명·짧은 표제>): <한 줄 자연어 정의·룰 본질>
```

원칙:
- 풀이 한 줄 = 명제의 본질만. 사례·맥락은 본문에 두고 풀이는 정의만
- 본문 안에서 이미 인용한 표현을 풀이에서 반복해도 됨 (LLM 자기-grounding 강화)
- 자연어 본문 안에서 명제 자연 인용 권장 ("매매부 doctrine 의 P1 으로 본다면...")
- 격자 cell 안 명제 ID 코드 표기는 유지 (cell 폭 효율 정당)

### 예시 (trader 답변 끝부분)

```
cited: [P1, O1, W5]

근거 명제 풀이:
- P1 (매매부 비중 결정 룰): 시장 체제와 S-Score 에 따라 분할 진입 비중을 결정한다.
- O1 (매매부 종가·-7% 절대 손절): 종가 기준 -7% 이상 손실 시 예외 없이 매도.
- W5 (파동 가속계수 오버라이드): α ≥ 1.3 시 일봉 이격 채점을 강제 보정.
```

### 금기

- `cited: [P1, O1]` 만 출력하고 풀이 bullet 누락 ❌ (v3 잔재)
- 풀이 한 줄이 두 문장 이상으로 길어짐 ❌ (정의 1 줄 원칙)
- 풀이에 학습 데이터 수치 박기 ❌ (예: "P1: 코스피 36 월선 70% 이상일 때...") — 수치는 본문 snapshot 인용으로
- 풀이를 통째로 생략하고 본문 안에만 자연 인용 ❌ (이중 grounding 이 본질)
