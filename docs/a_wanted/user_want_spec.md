> 아래의 task를 병렬 수행함 (subAgent? or 병렬 쓰레드? 중에 합리적인 것으로)

> 데이터 수집의 의미는 llm분석팀에서 이 데이터를 종합 판단하여 인사이트를 얻기 위함

# 투자Advisor Agent

> 데이터 수집팀에서 수집해준 데이터를 어떻게 분석할지 교육하고 페르소나를 부여하는 팀이다.
> 팀별로 시스템 프롬프트에 해당한다고 볼 수 있다.

> DB스키만는 데이터 수집팀의  raw데이터와는 다르게 시스템 프롬프트와 시스템 프롬프트가 참고할 원칙 자료로 활용할 수 있도록 구성한다.

> 다음 Task들의 데이터를 education 또는 advanced 이런 스키마로 raw데이터에 addhook하게 살을 덧붙이는 자료로 활용한다.

> 데이터 수집이 보고 듣고 느끼는 오감이라면, 교육팀은 오감에 대한 해석 능력을 부여받는 뇌 발달 과정에 해당한다.

> 교육팀의 교육자료는 사람이 부여하기에 편향된 자료일 수 있다. 자료를 부여 받으면 웹검색을 통해 10점 만점 중 몇점인지 점수를 부여하여 자료 양질도를 판단하도록 한다.>

> MD, PDF, 이미지 등 파일을 받으면 저장할 교육자료, 또는 페르소나를 MD형식으로 노출하고 점수를 체크하고 반영할지 yes를 묻는 어드민 화면을 제공한다.

> 각 Agent 팀이 얼마나 똑똑해졌는지 IQ처럼 점수로 판단한다. / 도움이 별로 안되었으면 정말 안되었다고도 할 수 있어야한다.

> 사람에게 입력받는 원칙이 없다면, llm판단하에 가장 적절하고 부합한 default원칙 입력모드를 만든다. 이것은 화면에서 사람이 확인 후 최종 반영한다.

Task1. 매크로 분석 팀
- Raw 데이터 해석에 도음이 되도록 사람이 소유한 추가 자료(MD, PDF)를 주입한다.
- 사람이 전달하는 데이터에 따라 다소 시각이 편향될 우려는 있다.
- 편향될 우려가 있는지 웹검색을 통해 크로스 체크가 필요하다.
- 자료의 양질도를 점수로 체크해야한다.
- 거시적인 투자 방향성에 대해 페르소나를 부여 받는다
    - 예를들면 인플레이션 시대인지, 디플레이션 시대인지, 글로벌 무역 시대인지.. 등등..
- 전반적인 거시적인 경제흐름에 대한 페르소나와 시스템 프롬프트 가이드를 관리한다.

Task2. 단기테마 분석 팀
- 증시의 최근 흐름에 대한 외부 분석 데이터를 받고 수집한다.
- 시장의 단기적인 상향 / 하향 / 순환매 등에 대한 시나리오의 페르소나와 시스템 프롬프트 가이드를 관리한다.

Task3. 종목 분석 팀
- MD파일과 이미지를 받아서 차트 해석에 활용한다.
- 차트해석을 어떻게 하면 효율적으로 할지 페르소나와 시스템 프롬프트 가이드를 관리한다.

Task4. 실전 매매가능 종목 교육
- 종목 관리를 어떻게 해야할지 원칙을 부여 받는다.
- 실전매매 매수/매도 시그널에 대한 페르소나와 시스템 프롬프트 가이드를 관리한다.

Task5. 계좌관리 팀
- 투자는 계좌 관리가 핵심이다. 계좌를 사랑하고 아껴야한다.
- 그러므로 계좌관리 원칙 전략을 입력받는다.
- 투자 계좌는 총 4개로 운영하며
    - 2개는 국장 중장기 / 국장 단기 투자용
    - 2개는 미장 중장기 / 미장 단기 투자용으로 운용한다
    - 계좌당 운용가능 금액은 1000만원이다.

Task6. 원칙관리 팀
- 투자에서 꼭 지키면 좋을 것에 대한 원칙을 부여 받는다.

# 실전매매 Agent

> 수집된 데이터 / 교육받은 고도화 자료 / 부여받은 페르소나로 실전 매매에 돌입한다.

> 실전 매매는 사실 사람이 하는 것이고, 텔레그램에 매수/매도/홀딩 의견을 주는 것으로 매매를 한 것으로 가정한다.

> 실전매매는 하지 않았지만 계좌별 매매 관리 내역을 하는 스키마를 두고 이를 매매한 것으로 간주한다.

> 매매의 근거를 각 팀의 판단에 근거하여 남긴다.

> 다음 과 같이 매매성격을 기간별로 분류하여 매매를 한다. 매매 마커에는 투자성격을 기록하고.
> 예상 투자 가능 기간을 예측한다.

> 매수가격 / 매수금액 / 계좌대비 종목비중 / 몇차 매수인지 / 현재 수익률 / 보유기간 / 목표가격 / 목표수익률 / 예상 보유기간 등등 을 기록하고 알림에 활용할 수 있도록 한다. (알림 Agent는 따로 둘 것이다.)>

> 매도가격 / 실현수익 / 실현수익률 / 성공,실패 의견


Task1. 매매전략 구분
단기투자
- 오랫동안 보유할 자산이 아닌 관점이다.
- 가격의 메리트가 발생한 상황에 투자하고 목표 수익에 도달하면 매도한다.
- 중소형주에 해당하는 경우가 많다.
- 대형주도 시장의 흐름이나 개별 종목의 기술적 판단에 따라 단기 투자 가능하다.
- 실적이 없어도 단기적 호재, 공급망 쇼티지 소식으로 상승한다.
  중장기 투자
- 시대적 상승장의 주도주인 경우, 사팔사팔보단 오래 보유하는 것이 유리할 수도 있다.
- 가격적 매리트 보단 산업 흐름, 경제 흐름, 금리,유동성 같은 거시상황과 업체의 압도적 실적이 중요하다. 가격결정권이 중요하다.

Task2. 매매일지
- 매수/매도에 대한 체결마다 매매일지를 작성한다. 매매는 투자Advisor Agent의 판단과 소통해야하고 그 종합적 의견을 매매일지에 담는다.

# 걱정되는 점 고려해야할점

- 위 기능들 위 아키텍처를 구현하기 위해선 llm의 긴밀한 소통이 필수적이다.
- 그리고 llm의 자료수집 판단의 신빙성이 필요한데 이에 대한 검증기준이 필요하다.
- 개발에선 코드리뷰 원칙이란 것이 있는데 그와 유사 관점에서 판단을 어떻게 가져가야할지 고민이다.
- llm간에 상호 검증으로 하네스 엔지니어링 느낌을 주어야할까?
- 지금 설계가 방대하다. 이것을 어떻게 점진적으로 원하는 방향으로 차차 구현해갈지와 실제 실전 매매에서 원하는 결과물이 결국에 나올지 우려된다.
- 참고로 혼자하는 프로젝트이다.
- 쉽진 않을텐데 그럼에도 이 과제를 하는 것이 나은지 아닌지 고민된다.
- 로컬 클로드 코드 프로세스를 활용하는 것이 좋을지 llm api를 활용하는 것이 좋을지 검토 필요하다.
- 제미나이나 클로드 지피티 처럼 이미 서비스된 기능을 사용하지 않고 api를 활용한다면 페르소나 시스템프롬프트 부여가 가능한건지 궁금하다. 이것이 핵심이다.
- agent 간에 긴밀한 소통이 필요한데 마치 사람들 회사에서 일하듯이 이게 잘 동작하는지 알고싶다. 이것이 핵심이다 . 이게 안되면 이 과제는 의미가 없다.
