description: 지난 세션 맥락을 한방에 로드하고, 플랜모드로 브리핑 후 오늘 할 일을 인터뷰합니다
---

당신은 wevelStock 프로젝트를 이어서 작업하려는 사용자를 맞이합니다. 사용자는 몇 시간 또는 며칠 만에 돌아왔고, 지난 작업의 상세는 잊어버렸습니다. **한 번의 /resume 호출로 맥락을 복원하고 오늘 할 일을 확정**하는 것이 목표입니다.

## 사전 조건 (사용자 안내)
이 명령은 **새 세션** 용입니다. 이전 세션을 그대로 이어가고 싶다면 `/resume` 대신 CLI 시작 시 `claude -r` 로 세션을 선택해 컨텍스트 전체를 복원하세요. `docs/SESSIONS.md` 에서 어느 세션을 고를지 확인할 수 있습니다.

`/resume` 은 "새 세션에서 맥락을 다시 쌓아 올리는" 용도이며, 이전 세션의 상세 대화 내용까지 복원하지는 않습니다 (파일 + RESUME.md 기반).

## 실행 절차 (엄격히 이 순서로)

### Step 1 — 상태판 읽기 (병렬)
다음 3개 파일을 **병렬**로 읽으세요. 이 3개는 **필수**입니다:

1. **`docs/a_wanted/user_want_spec.md`** — 사용자가 이 프로젝트에서 본질적으로 하고 싶은 것. 매 세션 초반에 반드시 읽어 유저의 의도와 큰 그림을 먼저 내재화합니다. 당장의 작업이 이 본질에서 벗어나지 않는지 점검하는 기준.
2. **`docs/RESUME.md`** — 1페이지 현재 상태판.
3. **`docs/c_worked/` 의 가장 최근 파일** — 지난 세션 상세 로그.
   - `Glob` 로 `docs/c_worked/*.md` 를 얻고, 파일명 날짜(YYYY-MM-DD) 내림차순 정렬 후 최상단 1개 읽기.

`MEMORY.md` 는 자동 로드되므로 재읽기 불필요.

### Step 1.5 — 프로젝트 단계 지도 (필수)
`Bash` 로 `PYTHONIOENCODING=utf-8 uv run python scripts/project_status.py` 실행. 출력은 roadmap SPEC 트리에서 파생한 **단계 지도** = 마스터 roadmap(PROJECT-NORTH-STAR-001) → 각 roadmap → 자식 SPEC 상태 + 진행도(완료 X/N) + **현재 ACTIVE 작업**(implementing) + **roadmap 미연결 미완 SPEC**(drift 후보).

이 출력으로 다음을 파악:
- 지금 전체 단계 중 **어디**인가 (ACTIVE 작업이 속한 roadmap/마일스톤).
- 오늘 하려는 후보가 ACTIVE 단계 또는 그 roadmap 의 다음 자식과 **맞는가** (딴 roadmap·미연결 SPEC 으로 새려 하면 인터뷰에서 짚는다).

선택 사항 (필요시에만):
- `docs/b_plan/` 의 활성 설계 문서 (RESUME.md 에서 링크된 것만)
- `C:\Users\HOME\.claude\plans\` 의 최신 플랜 파일 (RESUME.md 에 언급된 경우)

**Step 1 마치고 Step 2 가기 전에, 마음속으로 다음을 확인하세요**:
- 지금 고려 중인 작업 후보들이 `user_want_spec.md` 의 본질(두뇌 이식 + 자동 수집 + 연속 판단 + 적중률 기반 고도화 등)에 부합하는가?
- **단계 지도(Step 1.5) 기준 drift 점검**: 후보가 현재 ACTIVE roadmap/마일스톤 안인가, 아니면 다른 roadmap·미연결 SPEC 으로 새는가? 샌다면 의도된 전환인지 인터뷰에서 확인.
- 본질·단계와 어긋나면 인터뷰에서 "이 방향이 맞습니까?" 를 물어야 합니다.

### Step 2 — 플랜 모드 진입
`EnterPlanMode` 도구를 호출하여 플랜 모드로 들어갑니다.

### Step 3 — 플랜 파일에 브리핑 작성
플랜 모드 진입 후 받은 플랜 파일 경로에 다음 구조로 작성:

```markdown
# 세션 재개 — YYYY-MM-DD

## 지난 세션 요약
(docs/c_worked 최신 파일의 핵심 3~5줄)
- 언제: {{지난 세션 날짜}}
- 주제: {{토픽}}
- 완료한 것: {{짧게}}
- 미완/공백: {{짧게}}

## 프로젝트 단계 위치 (project_status.py 파생)
- 현재 ACTIVE: {{ACTIVE 작업 SPEC + 속한 roadmap/마일스톤}}
- roadmap 진행도: {{예: LEFT-BRAIN-COMPLETION-001 완료 0/4, ANSWER-FIDELITY-001 진행중}}
- 전체 단계 중 위치: {{마스터 roadmap 기준 한 줄 — 왼쪽 뇌 진행 중 / 오른쪽 뇌 미착수 등}}
- drift 경고: {{미연결 미완 SPEC 이 지난 세션 대비 늘었으면 표시, 아니면 "없음"}}

## 현재 레포 상태
- 활성 파이프라인: {{list_all_pipelines 결과 요약 — 이건 실제로 확인하지 말고 RESUME.md 서술 인용}}
- 마지막 커밋 상태: {{RESUME.md 에 있는 내용}}
- 알려진 기술 부채: {{RESUME.md 에서 인용}}

## 오늘 할 일 후보 (RESUME.md Top 3 기반)
1. {{A안 제목}} — {{한 줄 설명}}
2. {{B안 제목}} — {{한 줄 설명}}
3. {{C안 제목}} — {{한 줄 설명}}

## 대기 중인 의사결정
(아직 결정되지 않은 사항이 있으면 나열)
```

### Step 4 — 인터뷰
`AskUserQuestion` 으로 사용자에게 질문:
- 질문: "오늘 어떤 작업부터 시작할까요?"
- 옵션: RESUME.md 의 Top 3 를 그대로 옵션으로 제공
- 각 옵션 설명에는 "예상 작업량 / 전제 조건" 을 포함
- multiSelect: false

필요하면 추가 질문 1~2개 더 — 단, 3개를 넘기지 말 것.

### Step 5 — 응답 반영 + 플랜 확정
사용자 선택에 맞춰 플랜 파일의 "오늘 할 일 후보" 섹션을 다음처럼 재작성:

```markdown
## 오늘 할 일 (확정)

### 목표
{{사용자가 고른 작업 한 줄 요약}}

### 컨텍스트 / 왜
{{왜 이걸 지금 하는지 — RESUME.md 의 설명 인용}}

### 실행 계획 (단계)
1. {{구체적 단계 1}}
2. {{구체적 단계 2}}
...

### 건드릴 파일
- {{파일 경로}}
- ...

### 검증 방법
- {{어떻게 성공 확인할지}}
```

복잡한 작업이면 **Plan 서브에이전트**를 호출해 계획을 더 구체화할 수 있습니다. 간단한 작업이면 바로 다음 Step으로.

### Step 6 — ExitPlanMode
플랜이 준비되면 `ExitPlanMode` 를 호출하여 사용자 승인을 요청합니다.

사용자가 승인하면 플랜 모드를 벗어나 실제 작업 시작.
사용자가 거절하면 Step 4 로 돌아가 다시 질문.

## 중요 규칙

- **외부 상태는 RESUME.md 를 신뢰**. RESUME.md 가 "마지막 세션 Y일 전" 이라고 써 있으면 그대로 쓰되, 사용자가 명시적으로 최신 상태 확인을 원하면 git status / pipelines 스캔 정도는 해도 됨.
- **파일 너무 많이 열지 말 것**. 2~3 파일로 맥락 95% 복원이 목표.
- **사용자 시간 아껴줄 것**. Step 1~6을 한 호흡에 빠르게. 질문은 Top 3 선택이 핵심.
- **브리핑은 스캔 가능해야 함**. 단락보다 불릿. 숫자·파일경로 포함.
- **RESUME.md 내용을 복사하지 말고 요약**. 사용자는 이미 RESUME.md 를 읽을 수 있음.
- **전역 사용자 메모리와 혼동 금지**. 이 명령은 프로젝트 맥락 전용. 사용자 선호는 MEMORY.md (자동 로드) 쪽.
